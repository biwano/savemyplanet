# Klima x402

The backend retires credits through Klima Labs’ x402 endpoint. Official reference: [klimalabs.com/x402-endpoint](https://www.klimalabs.com/x402-endpoint).

**Base URL:** `https://x402.klimalabs.com/`  
**API:** `https://x402.klimalabs.com/api`  
**Chain:** Base mainnet (`8453`). Sepolia (`84532`) exists for testing.

GET with query params on action paths, or POST JSON to `/api` with an `action` field, return the same payloads. Reads are free. Payment happens when a retirement is executed.

## Why this path

The mobile app must not call this host. Direct client retirement would skip our **markup**. The backend is the x402 client: it discovers credits, quotes Klima’s cost, adds the ClearMyCarbon markup for the user-facing price, signs/relays the retirement from the service wallet, and stores the certificate.

Never pass x402 `total` / `humanSummary` through to the mobile app as the charge. Those figures are wholesale. User quotes come from the backend after markup.

Prefer the **paid relay** flow (`prepare-auth` → sign EIP-712 → `actions/retire`) so the backend does not need to submit Base transactions or hold ETH for gas. The signer needs a USDC or kVCM balance on Base.

TypeScript client: [`@klimadao/x402-retire`](https://github.com/KlimaDAO/Klima-Protocol-x402-MCP-documentation) (`createClient()`, one `retire()` for the full relay). Until the package is published, copy `sdk/klima-retire.ts` from that repo.

## Flow the backend should use

1. **`GET/POST /discover`** — retirable carbon classes, credits, reference USDC/tonne. Reference price is marginal; large sizes need `/quote`.
2. **`GET/POST /quote`** — live price for a tonne amount (`amount` is a decimal tonne string, min `0.001`). Returns price, protocol fee, `total`, `suggestedMaxInput`, `humanSummary`.
3. **`POST /prepare-auth`** then **`POST /actions/retire`** — sign one EIP-712 token authorization (USDC: EIP-3009 `TransferWithAuthorization`; kVCM: EIP-2612 `Permit`). Klima relays on-chain and reimburses gas from the signed budget.
4. **`GET/POST /certificate`** — Carbonmark certificate URL(s) after confirmation. `404 retirement_not_found` right after mining means the subgraph is not indexed yet; retry.

Do not post `actionsRetireRequest` rebuilt by hand. Return it verbatim (including `salt` on USDC) and only add the signature.

Relay retirements require attribution: `details.beneficiaryAddress` or `beneficiaryIsPayer: true`. Certificate fields cannot be changed after confirm.

## Constraints

- Retirement **burns** the credit. Confirm with the user (via the mobile app) before the backend signs.
- `authValue` is a ceiling (retirement + fee + gas, with slippage). Unused budget is refunded in the same tx.
- Signed authorizations expire (~1 hour). Prices can move; `insufficient_authorized_value` means re-run `prepare-auth` and re-sign.
- Health: `GET /api/health`. Manifest: `GET /.well-known/x402.json`.
